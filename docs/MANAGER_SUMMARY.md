# Отчёт для менеджера: TW — компилятор виджетов Telegram (Bot API 10.4)

## 1. Что это за проект простыми словами

В ноябре 2026 года Telegram выпустил **Bot API 10.4** с поддержкой интерактивных **HTML-виджетов прямо внутри сообщений чата** (Profile 1). В отличие от Mini Apps, виджет работает без интернета в жёсткой песочнице и имеет строгие лимиты:
- сжатый размер (zlib-9) — **не более 3 800 байт** (жёсткий потолок Telegram — 4 096 байт);
- сырой HTML — **не более 32 768 байт**;
- живое состояние (`chat_data`) — **не более 1 024 байт**;
- запасная текстовая подпись (`caption` для старых клиентов) — **не более 1 024 знаков**;
- высота в чате при ширине 320 px — **не более 560 px**.

**TW** — это детерминированный компилятор, который берёт структурированное JSON-описание интерфейса (от системы SAYF или от ИИ-помощника) и автоматически превращает его в безопасный, сверхкомпактный HTML-виджет, гарантированно укладывающийся в лимиты Telegram.

---

## 2. Что уже сделано

1. **Полное ядро компилятора (без внешних зависимостей)**
   - Реализован весь каталог из **14 компонентов**: карточка (`Card`), шапка (`Header`), текст (`Text`), статус-бейдж (`StatusBadge`), таблица «ключ–значение» (`KeyValue`), строка задачи (`TaskItem`), список со страницами (`List`), таблица (`Table`), полоса прогресса (`ProgressBar`), столбчатая диаграмма (`BarChart`), вкладки (`Tabs`), аккордеон (`Accordion`), ряд кнопок (`ButtonRow`) и разделитель (`Divider`).
   - Встроена строгая валидация: компилятор проверяет все лимиты и возвращает понятный список ошибок с точными JSON-путями, никогда не «падая» с исключением.
   - Встроена защита безопасности: модель и бэкенд не могут передать сырой HTML или JS; все строки экранируются, нулевой байт `U+0000` вычищается, ссылки пропускаются только по белому списку HTTPS-доменов, `innerHTML` не используется нигде.
   - Работают все **5 эталонных бизнес-сценариев**:
     - карточка задачи (со сменой статуса и прогресса вживую);
     - список из 8 задач на день кириллицей с локальными страницами (влезает в **2 220 Б** zlib-9 при лимите 3 800 Б);
     - карточка согласования решения (Одобрить / Исправить / Отклонить);
     - ответ ИИ-помощника с источниками и кнопкой озвучки;
     - короткий отчёт руководителя с графиком, KPI и вкладками.

2. **Веб-студия и интерактивная песочница (TW Studio)**
   - Можно прямо в браузере редактировать JSON-описание виджета и видеть результат в реальном времени внутри рамки чата Telegram шириной 320 px (в светлой и тёмной темах).
   - Есть реальный замер сжатого размера через Node `zlib` уровня 9 (как на сервере Telegram), визуальные индикаторы всех 5 бюджетов и предпросмотр запасного `caption`.
   - Можно тестировать живые нажатия кнопок, имитировать ответы и ошибки бота (`TIMEOUT`, `RATE_LIMITED`) и отправлять обновления `chat_data` (`editMessageWidgetData`), наблюдая, как виджет обновляется без переотправки сообщения.
   - Готовый экспорт: скомпилированный HTML, готовый JSON для метода `sendWidget` Bot API 10.4, JSON Schema и инструкция `promptGuide()` для ИИ-ядра.

## 3. Какие улучшения внесены сверх базового плана (по итогам инженерного ревью)

1. **Умная авто-свёртка (деградация) с учётом причины переполнения**
   - Если виджет не влезает по **высоте** (> 560 px), компилятор сворачивает второстепенные тексты в раскрывающиеся блоки и уменьшает размер страницы списка — не трогая кнопки действий.
   - Если виджет не влезает по **байтам zlib-9**, бесполезные для сжатия шаги (оборачивание в `<details>` и пагинация) автоматически пропускаются — сразу применяется усечение длинных текстов с сохранением полного текста в `caption`.
2. **Защита от новых статусов на бэкенде (`"*"` fallback)**
   - Если SAYF в будущем пришлёт новый статус в уже отправленный виджет, статус-бейдж корректно покажет запасную подпись вместо «зависшего» старого статуса.
   - Сама карта статусов внутри HTML упакована в компактные кортежи для экономии байтов.
   - Если у пользователя не осталось доступных кнопок (`act: []`), пустой ряд кнопок полностью скрывается и не оставляет пустого места.
3. **Нативное поведение в Telegram**
   - Добавлен лёгкий тактильный отклик (`HapticFeedback`) при нажатии кнопок действий.
   - Выбранная страница списка и активная вкладка сохраняются в `sessionStorage` (защищённом `try/catch`, чтобы не падать в веб-превью), поэтому виджет не сбрасывается при пересоздании клиентом.
4. **Автоматические инструменты контроля качества**
   - `npm run check:profile1` — мгновенная проверка всех 7 пресетов на детерминизм (SHA-256), лимиты Telegram, отсутствие запрещённых CSS/HTML/JS-конструкций Profile 1 и устойчивость к XSS-атакам.
   - `npm run weigh` — консольный профилировщик, показывающий, сколько сжатых байт zlib-9 «весит» каждый блок виджета (`<style>`, `<script>` и каждый компонент).

## 4. Что ещё остаётся на следующие этапы интеграции в SAYF

- Подключить официальную песочницу Telegram (`vendor/widget-sandbox` с QuickJS + Chromium) и Go-мок `telegym` в CI — исходные спецификации и скрипты сохранены в корневом архиве `tw-handoff.zip`.
- Перенести чистую библиотеку `src/tw/` в пакет `packages/telegram-widgets` веб-репозитория SAYF и подключить к шлюзу бота (веб-студия `src/App.tsx` и `server.ts` остаются отдельным инструментом разработки и в пакет шлюза не входят).
